## 升级中撞上的问题：迁移编号历史分叉

生产库的 alembic 版本表停在 `'0046'`——那是**老编号时代**的 parser_tier（本分支曾把这份变更编为 0040、后改号 0046，旧镜像已应用）。新编号里 `'0046'` 是上游的暂存附件迁移：新 api 把它当已应用、跳过，0047–0054 照常尝试，到 0055（parser_tier 现编号）撞上 `tier 列已存在`，事务整体回滚（库无损，版本表仍 '0046'）。

### 处理

1. **0055_parser_tier 加幂等守卫**（KnowWork 分支 `677ab02`）：按 `document_parser` 是否已有 `tier` 列识别老编号时代的库，整段跳过；downgrade 对称守卫。全新安装不受影响。迁移回归（新库升 heads 再退回）通过。
2. **版本表拨回真实状态**：`UPDATE alembic_version SET version_num='0045' WHERE version_num='0046'`（已核实 0001–0045 与 v0.0.6 逐字节相同，拨号成立；acme_0003 行不动）。
3. 重建 server/ext 镜像，重新 `install.sh --no-pull`：0045→0046→…→0054 照常补齐，0055 守卫跳过 DDL，最终版本表 `0055 + acme_0003`。

## 0. 关键事实（决定设计形态）

1. **注入的接缝已建好且带保护**：`conversations/turn_context.py` 的 `TurnContextHook`——扩展启动时 `ctx.turn_context.set(provider)` 登记一个提供者，每轮发消息前被调一次（`conversations/service.py:251 _with_context`，只对 followup 轮）；3 秒超时、出错或超时这一轮就不带，**不挡回答**。产出两段文字 `TurnContext{standing≤8000字, turn≤4000字}`（`kernel/contract.py:92`）。
2. **宿主侧已处理缓存与投影**：`runtime-host/plugins/dsh-host/src/turn-context.mjs` 把两段包进 `<system-reminder>` 以用户消息追加——standing 按内容摘要去重（不变不重发、不动前缀缓存；变了追加并注明取代；被压缩掉重发；从有变空追加「不再适用」），turn 紧跟提问后追加一次；只给根会话；业务库投影不认这种 source 的消息，不会漏进用户气泡。
3. **提取的时机钩子已建好**：`conversations/summaries.py:37` 的 `TurnEnded`（workspace、conversation、turn、question/answer 全文、status、user_id）经 `ApiContext.on_turn_ended`（即 `summaries.contribute`）登记；返回的字典写进 `run_summary.facts[名字]`，返回 None 不写。**注意 `run_summary` 不存回答全文**，回答要传就得放进任务载荷。
4. **后台任务框架现成**：PG 队列 + `JobRunner`。`enqueue` 在调用方事务里写 `job` 表（按 workspace+kind+subject 合并排队中的同类任务、载荷换新），worker 侧 `ctx.runner.register(JobKind, handler, on_give_up, on_retry)`；任务行所在空间由框架声明（`db/base.py` 的 current_workspace 注释），RLS 表照常可读。池随任务类型声明（`JobKind.pool`，执行槽数从注册的任务类型推导）：重下游自带池、不挤默认 core 池是仓库的既有纪律（MinerU 有自己的名额池）。
5. **模型调用现成且分额度**：`models/client.py:70 ModelClient`——`chat(response_format=…)` 原样透传厂商做结构化输出，`embed()` 按 32 条分批，后台/交互各一份并发额度；`capable(workspace, capability)` 供设置页选模型。业务服务与 worker 都拿得到（ApiContext.models / WorkerContext.models）。
6. **显式「记住」工具的位子留好了**：`tools/provided.py` 的 `ProvidedTools.add(ProvidedTool)`，排在内置工具后、MCP 前；`ToolSpec` 的 `answer_modes` 注释点名「用户明确要记的记忆写入」可以在快速问答里也提供。前端 `chat.tools` 插槽的类型注释里已经写好了示例：「记住：回答用表格」、notice 链接 `/settings?tab=memory`。
7. **前端插槽现成**：`web/src/features/settings/SettingsPage.tsx` 内置四个标签页后拼 `slotItems('settings.tabs')`，`?tab=` 深链已支持（docstring 举的例子就是「管理记忆」）；`settings.tabs` 收 `TabItem{key,label,children}`。
8. **记忆表是全局表**：记忆跟着人走、跨空间（在 A 空间说「回答用表格」，B 空间也生效），所以**不进 `RLS_TABLES`**，走 `global_sessionmaker`，照 identity 的表（`identity/models.py`）。扩展自带迁移分支（`tests/extensions/demo_migrations/` 是官方模板：独立 revision 序列 + `branch_labels` + `depends_on` 主线版本）。
9. **渠道账号没有记忆**：`TurnContextRequest.user_id` 是会话所属账号，渠道会话是渠道账号（`kind=channel`，不能登录、没有「本人」）。凡 memory 链路都先查 `profiles` 的 kind，channel 一律跳过。

## 1. 范围与决策记录

| 决策 | 取舍 | 理由 |
|---|---|---|
| 记忆挂在谁身上 | **用户**（user_id），跨空间，不进 RLS | 记忆是「关于这个人」，不是「关于这个空间」；空间级记忆（进 RLS）留给二期 |
| v1 状态集 | 生效中 / 待确认 / 已被更新 / 已归档；`watch`（观察中）枚举值预留、二期启用 | 状态少一半，UI 与整理逻辑都简单一截；加状态不用迁移 |
| 提取后直接生效吗 | 置信度 ≥0.8 且不与现有记忆冲突 → **直接生效**；否则进待确认 | 全走人工确认没人用；待确认队列兜住低置信与冲突 |
| 生效上限 | **200 条**（对照参照产品 198/200） | 注入预算可控（见 §4）；满了走「整理」的腾位规则（§7） |
| 相似度怎么做 | embedding 存 **JSONB 浮点数组，Python 里算余弦** | 每用户 ≤200 行，200×1024 维进程内毫秒级；不引 pgvector、不加部署依赖 |
| 谁能看 | **只有本人**。管理后台不做任何记忆查看入口，系统管理员也不行 | 个人数据的最小可见；私有化部署的合规话术 |
| API Key | 鉴权用 `ctx.principal(None)`（本人身份，不设 Key 范围要求），与企业扩展包一期一致 | 个人 Key 也是本人身份，风险等价 |
| 记住工具的审批 | `risk="write"` + `approval="never"` | 高频低风险、内容明示在回答下方（notice）、随时可在设置页删除——用透明度替代弹窗；保守部署可改成默认审批（§6 有备选） |
| 渠道账号 | 不参与（不注入、不提取、无页面数据） | 渠道会话没有「本人」；`turn_context.py:22` 注释已提示要分 kind |
| 模型从哪来 | 环境变量 `ACME_MEMORY_CHAT_MODEL` / `ACME_MEMORY_EMBED_MODEL` 指定别名；没配就取该空间 `capable()` 的第一个 | 零配置可用；要钉模型的管理员有口子 |
| 提取留不留出处 | 每条提取记忆带 `quote`（用户原话逐字摘录 ≤200 字），待确认页与编辑里可见 | 判断「确认/忽略」要看出处，也留审计依据（借鉴 octop-memory 的证据链） |
| 企业能不能整体关 | **空间级开关**（默认启用，空间管理员停用本空间）+ 个人开关，两级都开才工作 | 企业私有化部署第一个被问的就是这个；停用只停链路，数据保留、随时恢复 |
| 记账与衰减的范围 | mention 只记 turn 段命中（与提问真正相关的）；降权只降 fact/focus 且系统提取的 | standing 常驻 ≠ 提到——按「在场」记账会让衰减永不触发；偏好稳定、在办靠期限，都不该衰减 |
| 记忆在哪提取的 | 记 `origin_workspace_id`（不判权，只做排查与重嵌向量时的模型路由参考） | 整理任务要选模型路由的空间；排查「这条哪来的」也要看 |

## 2. 数据模型（扩展自己的迁移分支）

新模块 `acme/kw_enterprise/memory/models.py`，登记进 Extension 的 `model_modules`；迁移目录 `memory_migrations/`，`revision = "acme_0001"`、`branch_labels = ("acme",)`、`depends_on` 写当前主线最新版（装包时以实际为准，如 `0040`）。两张表都是全局表，`rls_tables = ()`。

```python
"""记忆表：个人的、跨空间的（identity 同款：全局表，不进 RLS_TABLES）。"""

from datetime import datetime
from sqlalchemy import Boolean, CheckConstraint, DateTime, Float, ForeignKey, Index, Integer, String, Text, func
from sqlalchemy.dialects.postgresql import JSONB
from sqlalchemy.orm import Mapped, mapped_column

from knowwork_server.db.base import Base

PREFERENCE, FOCUS, FACT, TASK = "preference", "focus", "fact", "task"        # 偏好/长期关注/事实/在办事项
EXTRACTED, BY_USER, BY_TOOL = "extracted", "user", "tool"                     # 系统提取/手动添加/会话记住
ACTIVE, PENDING, WATCH, SUPERSEDED, ARCHIVED = "active", "pending", "watch", "superseded", "archived"
ACTIVE_CAP = 200
CONTENT_MAX = 500


class Memory(Base):
    __tablename__ = "memory"
    __table_args__ = (
        CheckConstraint("type in ('preference', 'focus', 'fact', 'task')", name="ck_memory_type"),
        CheckConstraint("source in ('extracted', 'user', 'tool')", name="ck_memory_source"),
        CheckConstraint("status in ('active', 'pending', 'watch', 'superseded', 'archived')", name="ck_memory_status"),
        CheckConstraint(f"char_length(content) between 1 and {CONTENT_MAX}", name="ck_memory_content_len"),
        Index("ix_memory_user_status", "user_id", "status"),
    )

    id: Mapped[str] = mapped_column(String(40), primary_key=True)   # mem_<uuid hex>，照 job_<hex> 的命名办法
    user_id: Mapped[str] = mapped_column(String(32), ForeignKey("user.id", ondelete="CASCADE"), index=True)
    type: Mapped[str] = mapped_column(String(16))
    content: Mapped[str] = mapped_column(Text)
    quote: Mapped[str] = mapped_column(Text, default="")   # 提取时的用户原话逐字摘录（≤200 字，应用层截断）；手动添加/工具写入为空
    source: Mapped[str] = mapped_column(String(16), default=EXTRACTED)
    origin_workspace_id: Mapped[str | None] = mapped_column(String(64), nullable=True)  # 在哪个空间提取的；只做排查与模型路由参考，不判权
    status: Mapped[str] = mapped_column(String(16), default=PENDING)
    score: Mapped[float] = mapped_column(Float, default=1.0)        # 提取置信度起步，整理时衰减（§7）
    embedding: Mapped[list[float] | None] = mapped_column(JSONB, nullable=True)      # 写入时算，失败留空
    embedding_model: Mapped[str | None] = mapped_column(String(100), nullable=True)  # 算向量用的别名；换了模型维度可能不齐
    mention_count: Mapped[int] = mapped_column(Integer, default=0)
    last_mentioned_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True), nullable=True)
    expires_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True), nullable=True)  # 在办事项到期归档
    superseded_by: Mapped[str | None] = mapped_column(String(40), nullable=True)  # 被哪条新记忆取代（审计链）
    created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now())
    # onupdate 由 ORM 在 UPDATE 语句里带上：编辑/整理动过之后时间是真的，衰减也按它算
    updated_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now(),
                                                 onupdate=func.now())


class MemorySetting(Base):
    """个人记忆开关；没有行 = 默认开启。last_organized_at 兼作「今天整理过没有」的标记。"""

    __tablename__ = "memory_setting"

    user_id: Mapped[str] = mapped_column(String(32), ForeignKey("user.id", ondelete="CASCADE"), primary_key=True)
    enabled: Mapped[bool] = mapped_column(Boolean, default=True)
    last_organized_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True), nullable=True)
    updated_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now())


class MemoryWorkspaceSetting(Base):
    """空间级开关（企业合规口）：默认启用；停用后本空间的注入、提取、记住工具全停，个人数据保留。
    全局表（访问由扩展自己的路由管，判空间管理员经 ApiContext.access），不进 RLS_TABLES。"""

    __tablename__ = "memory_workspace_setting"

    workspace_id: Mapped[str] = mapped_column(String(64), primary_key=True)
    disabled: Mapped[bool] = mapped_column(Boolean, default=False)
    updated_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now())
```

要点：

- **删除是物理删除**（用户点了删就是删，隐私预期）；「已归档 / 已被更新」是系统降级，用户可恢复、可再删。清空 = 按用户物理删全表。
- `superseded_by` 不设外键约束也行（简化恢复语义），文档层面保留指向即可——实现时二选一，倾向不设 FK。
- `watch`（观察中）一期不写入，但校验与 UI 文案先备好，二期启用不用动表。

## 3. 状态机

```
                    conf ≥0.8 且无冲突              conf <0.8 或与现有记忆冲突
  提取候选 ────────────────────► 生效中 ◄──────── 确认 ─── 待确认
  「记住」工具 / 手动添加 ─────► 生效中                  │ 30 天未处理（整理）
                                        │ replace 判定   ▼
                                        ▼            已归档 ◄── 到期(expires_at) / score<0.15 / 上限腾位（整理）
                                     已被更新 ────────────────► 恢复（生效未满时）
  任意状态 ── 用户删除/忽略/清空 ──► 物理删除
```

| 从 | 事件 | 到 | 谁做 |
|---|---|---|---|
| （无） | 提取候选，置信度 ≥0.8、判重无冲突 | active | 提取任务 |
| （无） | 提取候选，置信度 <0.8，或 LLM 判重失败 | pending | 提取任务 |
| pending | 用户点「确认」 | active（满 200 则 409） | API |
| pending | 用户点「忽略」 / 30 天未处理 | 物理删除 / archived | API / 整理任务 |
| active | 新候选判重=replace 且高置信 | superseded（`superseded_by`=新 id），新记忆 active | 提取任务 |
| active | `expires_at` 到期（在办事项）；score 衰减到 <0.15；生效满 200 腾位 | archived | 整理任务 |
| archived / superseded | 用户点「恢复」 | active（满 200 则 409，提示先删几条） | API |
| 任意 | 用户删除 / 清空 | 物理删除 | API |

## 4. 注入链路（turn_context 提供者）

`extension.py` 装配时 `ctx.turn_context.set(provide)`，`provide` 拿到 `TurnContextRequest{workspace_id, user_id, conversation_id, text, answer_mode}`。3 秒预算内只做一次 DB 读 + 至多一次 embed 调用：

```python
async def provide(request: TurnContextRequest) -> TurnContext:
    if await is_channel_account(request.user_id):          # profiles 查 kind，channel 不带
        return TurnContext(standing="", turn="")
    if await workspace_disabled(request.workspace_id):     # 空间级开关（§1）：本空间整条链路停
        return TurnContext(standing="", turn="")
    setting = await load_setting(request.user_id)          # memory_setting，无行=开启
    if not setting.enabled:
        return TurnContext(standing="", turn="")           # 宿主会追加「不再适用」，把旧记忆从上下文摘掉
    memories = await load_active(request.user_id)          # ≤200 行一次查完（全局表，global_sessionmaker）

    standing = format_standing(memories)                   # 确定性生成：见下
    turn_seg = await format_turn(request.text, memories)   # active>10 才做 embed+余弦；否则 ""（全在 standing 里，不重复）
    track_mentions(hit_ids(turn_seg))                      # fire-and-forget：只记 turn 段命中的那几条（见下）
    enqueue_organize_if_due(setting, request)              # 当天第一次：顺手入队整理（best-effort，
                                                           #   global_sessionmaker 开事务 + set_workspace 后 enqueue，见 §5）
    return TurnContext(standing=standing, turn=turn_seg)
```

**standing 段（预算自限 2500 字，总量由契约的 8000 字兜底）**——偏好与在办事项无条件进（量小价值高），事实与长期关注按 score 取前 20 条；排序固定（偏好→在办→事实→关注，组内 score 降序、id 升序），内容不变时宿主不会重发，前缀缓存不受扰动：

```
以下是关于这位用户的长期记忆，回答时参考；与当前提问冲突时以提问为准。
【偏好】回答用表格
【在办】正在核对 2026 年第三季度各区域净收入（2026-11-03 起，11-30 前）
【事实】2024 年销售费用总额 20,900 元，其中业务招待费 4,500 元
【关注】数据集起草、公司列表查询
```

**turn 段（预算自限 1500 字）**——把本轮 `request.text` embed 一次（`background=False` 走交互额度，几十毫秒），与 200 条记忆算余弦，取 ≥0.35 的前 10 条，`【相关记忆】`前缀罗列。embed 失败或超时就空着——standing 已经保底。active ≤10 条时直接给空串：全部记忆已在 standing 里，再挑一遍只是重复占预算，还白花一次交互额度调用。子会话拿不到这段（宿主只给根会话），不用操心。

**记账与顺手整理**：`asyncio.create_task` 写 mention 记账——**只记 turn 段命中的条目**（这一轮的提问真的用上了它）。standing 常驻不算提及：偏好、在办每轮都在 standing 里，按「在场」记账的话 mention_count 会随轮数膨胀、`last_mentioned_at` 永远是今天，§7 的衰减就永不触发——记账要表达「相关」，不是「在场」。`last_organized_at` 日期不是今天就在新事务里 `enqueue(memory.organize, workspace_id=request.workspace_id, subject_id=user_id)`——吞异常，绝不影响本轮。整理任务按 workspace+kind+subject 合并，一天最多排队一条。

## 5. 提取链路（on_turn_ended → 队列 → worker）

**登记**：`ctx.on_turn_ended("memory", contribute)`。

**贡献者（api 进程，立即返回）**：查本人是真人、本人开关与该空间开关都开启（两项都查——空间停用后就不必白排任务）→ 开事务 `enqueue(memory.extract, workspace_id=ended.workspace_id, subject_id=ended.conversation_id, payload=…)`。`job` 表在 RLS 名单里，照 `RunSummaries._ended` 的写法：`global_sessionmaker` 开事务、`set_workspace(session, workspace_id)` 后再 enqueue。subject 用 conversation_id：同一会话连续几轮合并成一条任务、载荷换最新（§0 事实 4）。载荷自带回答全文（run_summary 不存）：

```python
{"user_id": ended.user_id, "conversation_id": ended.conversation_id, "turn": ended.turn,
 "question": ended.question[:2000], "answer": ended.answer[:6000]}
```

返回 `{"queued": True}`（写进 `run_summary.facts["memory"]`，运行记录里可见）；跳过时返回 None。

**任务类型**（api 与 worker 共用一份定义）：

```python
EXTRACT = JobKind("memory.extract", pool="memory", max_tries=3, lease_seconds=120.0, timeout_seconds=300.0,
                  retry_delays=SERVICE_DELAYS, version=1, cancelable=True, label="记忆提取")  # 自带池，不挤 core
```

**处理函数（worker）**：

1. 读载荷；守卫：本人开启、**空间开启（复查——入队后才停用的，队列里的存量任务不再跑模型）**、`question+answer` 合计 ≥40 字（寒暄跳过）。
2. **提取**：`models.chat(workspace_id, "…", prompt, response_format=EXTRACT_SCHEMA, max_tokens=1024)`，只对「已完成」的轮次（status=completed）跑。Schema 用 OpenAI 兼容的 `{"type": "json_schema", "json_schema": {"name": "memory_extraction", "strict": true, "schema": …}}`；个别厂商不支持时退 `{"type": "json_object"}` + 提示词约定，解析失败按「本轮无可提取」收尾（不是错误）。

```python
EXTRACT_SCHEMA = {"type": "json_schema", "json_schema": {
    "name": "memory_extraction", "strict": True,
    "schema": {
        "type": "object",
        "properties": {"memories": {"type": "array", "items": {
            "type": "object",
            "properties": {
                "type": {"type": "string", "enum": ["preference", "focus", "fact", "task"]},
                "content": {"type": "string", "description": "一句第三人称中文陈述，不超过 100 字"},
                "quote": {"type": "string", "description": "支撑这条记忆的用户原话，逐字摘录，不超过 200 字"},
                "confidence": {"type": "number", "minimum": 0, "maximum": 1},
            },
            "required": ["type", "content", "quote", "confidence"],
        }}},
        "required": ["memories"],
    }}}
```

   提取提示词的立场（写进系统消息）：只收**用户明确表达**的、跨会话仍有用的偏好/关注/事实/在办；不收寒暄、一次性细节、助手自己的话、只在本轮有效的中间结论；宁缺毋滥；`quote` 逐字摘录、不改写——否定与限定词必须原样保留，「以后不用表格」丢不得「不」字（借鉴 octop-memory 的防稀释规则）。

3. **纯规则前置（不花 LLM，借鉴 octop-memory 的晋升检查）**：
   - **签名去重**：候选 content 归一化（NFKC 折叠、casefold、空白折叠）后与本人 active 记忆的签名完全一致 → 直接丢弃，省一次判定调用。有意不折叠标点——「我会用」和「我不会用」不是同一句；
   - **否定极性冲突**：与某条 active 记忆共享 ≥3 个内容 token（英文按词、CJK 逐字，去中英停词）而否定词（不/没/别/勿、not/never/avoid…）极性相反 → 直接进 pending 并标记冲突。这种一眼能看的矛盾不劳烦 LLM，宁可保守（漏掉真冲突也行，反正落到了待确认）。
4. **LLM 判定**：剩下的候选先 `models.embed`（后台额度），与本人 active+pending 且有向量的记忆算余弦（维度不齐的跳过），取 ≥0.82 的前 3 条；有命中的候选**合并进一次**判定调用（每轮 LLM 预算封顶 2 次：提取 1 + 判定 1，借鉴 octop-memory 每候选至多 1 次升级的纪律）：

   ```json
   {"action": "noop | update | replace", "content": "update/replace 时的新表述"}
   ```

   - `noop`：同义重复，丢弃候选；
   - `update`：改写命中那条的 content（id 不变，`mention_count+1`、`last_mentioned_at=now`）；**防稀释**：改写不得丢失否定与限定词（「不用表格」不能改成「用表格」），拿不准就直录 `quote` 原话；
   - `replace`：命中那条 → superseded（`superseded_by` 指向新记忆），候选入库。
   判定失败/超时 → 候选进 pending（宁可待确认，不静默写错）。
5. **落库**：无命中的候选，置信度 ≥0.8 → active，否则 pending；`quote` 缺失或截断后为空的一律按低置信进 pending——证据不全的不直接生效，也不丢弃（用户可能想自己补出处）。task 类写入时 `expires_at = now + TASK_TTL_DAYS(30 天)`：期限不该让提取模型猜日期，默认一个月、用户可在编辑里改。行上记 `origin_workspace_id`（本任务的 workspace）。入库时顺带算 embedding（embed 失败留空，不影响生效）。active 满额走 §7 的腾位。

**模型没配**：`ModelCallError(retryable=False)` → `on_give_up` 记日志收尾，注入照常工作（standing 不依赖模型），用户无感。

## 6. 显式记忆工具（「记住」）

`ctx.tools.add(ProvidedTool(tool=BuiltinTool(spec, handler), available=available))`：

```python
ToolSpec(
    name="remember",
    description="把用户明确要求长期记住的偏好或事实写入他的个人记忆（之后的会话都会带上）。"
                "只在用户明确说「记住 / 以后都… / 别再…」时调用；一次一条，改写成一句第三人称的中文陈述。",
    input_schema={
        "type": "object",
        "properties": {
            "content": {"type": "string", "maxLength": 200, "description": "要记住的一句话，如「回答用表格」"},
            "type": {"type": "string", "enum": ["preference", "fact", "task", "focus"]},
        },
        "required": ["content"],
    },
    risk="write",
    approval="never",          # 见下方取舍
    concurrent=False,
    answer_modes=frozenset({"agent", "quick"}),   # 快速问答里用户说「记住」也要能记（ToolSpec 文档点名的场景）
    guidance="用户说「记住」时才用；写完用一句话向用户确认记了什么。",
)
```

- **handler**：channel 账号拒绝；先判重（与 active 近重复 → update），否则直接 active、`source=tool`、置信度视同 1.0，embedding best-effort；返回中文确认「已记住：回答用表格。可在 设置 → 我的记忆 中管理。」
- **available**：查本人开关 + 本空间开关，任一关就不给这个会话（宿主每会话拉一次清单，中途关掉也执行不了，`tools/provided.py` 语义现成）。
- **审批=never 的理由**：写的是用户本人的记忆列表，风险与「用户自己打一行字」等价；副作用在回答下方明示（notice），且设置页随时可删。要更保守就把这行删掉，回落到 write 的默认审批（每次弹确认）——一句话的改动，不影响其他设计。
- **前端显示**（`chat.tools` 插槽）：`{name: "remember", label: "记住", target: "content", notice: call => call.result 正常时 ({text: \`已记住：${content}\`, link: {label: "管理记忆", to: "/settings?tab=memory"}})}`——执行完在回答下方显示一行「已记住：回答用表格 · 管理记忆」。
- 「忘记」工具（按内容匹配删除）放二期：设置页已覆盖删除路径，对话里「忘掉」先引导去设置页。

## 7. 整理链路（立即整理 + 每日一次）

```python
ORGANIZE = JobKind("memory.organize", pool="memory", max_tries=3, lease_seconds=120.0, timeout_seconds=600.0,
                   retry_delays=SERVICE_DELAYS, version=1, cancelable=True, label="记忆整理")
```

载荷 `{"user_id": …, "workspace_id": …}`（subject=user_id，天然一天一条）。**workspace_id 只为 ModelClient 的模型路由**（按空间查模型目录），数据不按空间筛：提供者顺手入队用当前空间，「立即整理」从设置页发，页面知道自己所在的空间。入队前过三道闸（服务层判）：本人是该空间成员（workspace:use）、个人开关开着、空间开关开着。**人工优先**：整理只动 `source="extracted"` 的记忆——手动添加与「记住」写入的（user/tool）不参与自动合并、降权与腾位，只能本人改删（借鉴 octop-memory 的手动文档优先原则）。步骤固定顺序：

1. **过期清理**：pending 超 30 天、task 类 `expires_at` 已过 → archived。
2. **合并重复**：active 里余弦 ≥0.90 的对子（最多 20 对）交一次 LLM 判定合并改写，旧的 archived；判定不了就都留着。
3. **降权**：只对 **fact / focus 且 source=extracted** 的算——按 `last_mentioned_at`（没有就用 `created_at`）算整月数 gap，`score *= 0.85 ** gap`；`score < 0.15` → archived。preference 不衰减（量小、稳定，「回答用表格」不需要最近被提到才有效）；task 靠 expires_at；user/tool 来源见上条人工优先，永不自动动。
4. **腾位**：active > 200 → 从 score 最低的开始 archived 到 200 条。提取落库时若已满 200，也走这步：腾不出（都不够低）→ 新候选改落 pending。
5. **补向量**：embedding 为空或 `embedding_model` ≠ 当前嵌入别名的，批量重算（32 条一批）。
6. 完成后写 `memory_setting.last_organized_at = now`。

「立即整理」按钮 = API 入队同款任务（202 返回 jobId，前端轮询 counts）；「每天自动整理一次」不新加 cron 基建——§4 的提供者发现日期变了顺手入队，任务框架再合并并发请求。

## 8. API 设计（前缀 `/api/memory`，tags=["记忆"]）

全部用 `Annotated[Principal, Depends(ctx.principal(None))]`（本人身份）。错误映射：`NotFound → 404`、生效满额 → 409、校验失败 → 422；「清空」与「开关」走 `audit.context.annotate` 登记动作名，其余路由用自动派生名。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/memory?status=&limit=&offset=` | 按状态分页列表；回 `{items[], total}`，item 含 `{id, type, content, source, status, score, mentionCount, lastMentionedAt, expiresAt, supersededBy, createdAt, updatedAt}`（camelCase，同 web/src/api 惯例） |
| GET | `/api/memory/counts` | `{active, pending, superseded, archived, cap}`——页签角标与 200 上限 |
| POST | `/api/memory` | 手动添加 `{type, content}` → 201，`source=user`、直接 active（本人添加本人负责）；满额 409 |
| PATCH | `/api/memory/{id}` | 编辑 content / type / expiresAt；内容变更后旧向量置空，M3 整理时懒重算 |
| DELETE | `/api/memory/{id}` | 物理删除，204 |
| POST | `/api/memory/{id}/confirm` | pending → active；满额 409 |
| POST | `/api/memory/{id}/dismiss` | pending 忽略 = 物理删除，204 |
| POST | `/api/memory/{id}/restore` | archived / superseded → active；满额 409 |
| POST | `/api/memory/organize` | 入队整理，202 `{jobId}` |
| GET / PUT | `/api/memory/settings` | `{enabled}` 开关；关闭后注入给空、提取与工具全停，**数据保留**（重新打开接着用） |
| GET | `/api/memory/export` | 全状态导出 JSON 下载（数据可携带） |
| POST | `/api/memory/clear` | 物理清空本人全部记忆，204；前端二次确认 |

注意：路由不落 workspace 前缀（记忆跨空间、不属于某个空间的 `/api/workspaces/{ws}/…` 族），服务层用 `global_sessionmaker`。三个例外与细节：

- **空间开关**是唯一落 workspace 前缀的路由（空间管理员）：`GET / PUT /api/workspaces/{ws}/memory-setting`，体 `{disabled}`，动作进审计；管理员判定经 `ApiContext.access`（AccessService，具体方法实现时对照——判不了宁可 403，不放过）。
- **满额判定**（添加/确认/恢复）：事务内先 `pg_advisory_xact_lock(hashtext(user_id))` 再 count 再写——普通 count 不加锁，READ COMMITTED 下并发能把 active 顶过 200，锁把同一用户的「查+写」串行化（R1 审查后补）。
- `organize` 入队要带 workspace_id（模型路由用）：设置页发当前空间的 id。

## 10. 隐私与安全

- **只有本人可见**：路由按会话身份取 user_id，不收任何 user 参数；管理后台、审计、大盘都不展示记忆内容。
- **数据不出机房**：记忆存企业自己的 PG；模型调用走平台模型网关（与对话同路），不新增第三方依赖。
- **可携带、可遗忘**：导出 JSON、逐条删除、清空，全部即时物理生效；账号删除时 `ondelete="CASCADE"` 级联清掉。
- **渠道隔离**：channel 账号在注入、提取、工具三条链路的入口都被挡掉。
- **审计**：清空与开关留审计记录；逐条增删改是个人操作，不进管理审计（与用户改自己的昵称同级）。

## 13. 风险与不做的事

**风险**

- **上游契约漂移**：消费的接缝都在 `extensions/contract.py` 与 `slots/registry.ts`，上游承诺加法演进；内部模块 import（`summaries.TurnEnded`、`tools/registry.ToolSpec`）无承诺——照一期 §9 的纪律钉版本、升级前跑准入测试。
- **3 秒预算**：一次全局表查询（≤200 行）+ 一次 embed 交互调用，实测应在几十毫秒级；超时兜底是现成的（这一轮不带 turn 段）。不要在提供者里加任何 LLM 调用。
- **提取质量**：宁可少记（提示词立场 + 置信度阈值 + 待确认队列），错记忆的代价是用户信任；用户可编辑可删是最终兜底。
- **嵌入模型更换**：维度不齐的旧向量自动跳过相似度，整理任务懒重算补齐，不需要一次性迁移脚本。
- **standing 稳定性**：内容与顺序必须确定性生成（同输入同输出），否则宿主去重失效、前缀缓存反复失效；实现时用纯函数 + 固定排序。

**不做（二期以后）**

- 「建议给空间」：把个人记忆沉淀成空间级记忆或知识库条目——涉及 RLS 与授权，单独立项。
- 工作空间级记忆（团队共享的「这个空间的事实」）：进 `RLS_TABLES`，与个人记忆分开的表。
- 观察中状态：提取后先观察、被再次印证才生效的完整生命周期（枚举值与文案已预留）。
